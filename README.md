# Mr. Japan — Progress Experience (Reference Implementation)

גרסת reference ליישום חוויית ה-Progress, מיועדת למיזוג לריפו האמיתי של מר יפן.
נבנתה לפי צילומי המסך המאושרים (12/08) + מפרט ה-Demo האינטראקטיבי המלא.

## מודל המצב (v8) — currentStage מול previewStage
שני מושגים נפרדים ב-`App.tsx`:
- `currentStageId` — היכן הלקוח נמצא **בפועל** (מצב הפרודקשן). לעולם לא משתנה מלחיצה על תחנה בפס.
- `previewStageId` — איזה שלב **מודגם** כרגע (null = מציגים את השלב בפועל).

התנהגות:
- **מצב דמו (ברירת המחדל בפרוטוטייפ):** כל תחנה בפס (1..N) לחיצה — לחיצה קובעת `previewStage` ומרנדרת את השלב במלואו (כותרת, בעלות, הודעה, CTA, Sheet, "הבא:") — כאילו הסטטוס ב-Monday השתנה והלקוח פתח את האפליקציה באותו רגע. תת-מצב עם autoAdvance (תשלום/טופס נשלח) מתגלגל בתוך ה-preview בלבד.
- **מצב לקוח (מתג בפאנל ה-Demo):** עתידי נעול; שלב שהושלם נצפה כהיסטוריה לקריאה בלבד. במוצר האמיתי זו ברירת המחדל.
- ויזואלית בפס: ✓ טאופ = הושלם · עיגול כתום מלא ממוספר = השלב בפועל · טבעת כתומה חלולה ממוספרת = preview (לעולם לא נראה "הושלם") · שורת הספירה: "מציג: שלב 6 מתוך 10 · בפועל: שלב 3 ←".

## מה מיושם כאן
- רקע כרטיס ה-Progress: משטח שנהב חם ואחיד (`#fffcf6`) עם רמז יפני אחד בלבד — צללית פוג'י כווטרמרק בתחתית (5.5% שקיפות, 34–40px). בלי סאקורה/שמש/פגודה/גלים, בלי מסקוט ובלי לוגו בתוך הכרטיס. הרקע מוגבל לכרטיס בלבד — רקע הדף, מרקם האסאנוהה, ההדר, הניווט ומעטפת ה-iPhone לא נגעו.
- מותג: משפחת כתום גלימת מר יפן — טוקנים `--brand-orange-primary #F07226` (CTA/פעיל, ~3:1 לטקסט לבן מודגש) · `--brand-orange-deep #D25A15` (hover/טקסט) · `--brand-orange-light` (פילים) · `--brand-orange-subtle` (רקעים רכים); ✓ טאופ להושלם; אפור חם לעתידי; ירוק רק לאישורים.
- ברירת מחדל: שלבים 1–2 מושלמים, שלב 3 (פגישה) נוכחי — הגישה נפתחת אחרי תשלום השירות.
- **שתי שכבות בכרטיס המסע:** שכבה 1 בראש הכרטיס — פס התקדמות אופקי דק (התמצאות בלבד: "איפה אני במסע?") ומתחתיו "שלב X מתוך Y" + "כל שלבי המסע". שכבה 2 מתחת לקו מפריד — כרטיס אחד לשלב המוצג בלבד ("מה קורה עכשיו? מה עליי לעשות?"). אין הרחבה אנכית של כמה שלבים בו-זמנית.
- אין קיבוץ שלבים לפאזות/קטגוריות בקונפיג — ולכן לא הוצג ולא הוגדר כזה.
- היררכיית הכרטיס: אייקון קטן לצד שם השלב ← שורת מצב אחת (תג "נדרשת פעולה" · בעלות · מועד) ← שורת הקשר אחת לכל היותר ← שורות פעולה (רק כשיש פעולה אמיתית).
- סטטוס ובעלות: כשהכדור אצל הלקוח מוצג **"נדרשת פעולה"** בלבד (תג מתאר בכתום — סטטוס, לא כפתור) במקום קופי בעלות. בשאר המצבים מוצג צ'יפ בעלות ניטרלי: צוות מר יפן / ביחד עם צוות מר יפן / אין צורך בפעולה (+ דריסה הקשרית, למשל "צוות מר יפן · הזמנות"). הכתום שמור לפעולות הלקוח בלבד.
- Bottom Sheets: תשלום שירות · פרטי הפגישה · טופס שינויים (שליחה → "✓ קיבלנו" → מעבר אוטומטי) · בחירת מלונות ואטרקציות. שלבים בבעלות הצוות — ללא CTA מומצא.
- **מסע אדפטיבי לפי זמן-לטיול (`timeToTripScenario`):** הלקוח בוחר מלונות; עבור אטרקציות הפעולה היא תשלום בלבד. מקור האמת הוא `SELECTIONS_ACTIONS` ב-`journeyConfig.ts`, ו-`activeSelectionActions(paymentWindowOpen)` מחזירה את הפעולות הנדרשות כרגע — אין תנאים מקודדים ב-JSX. יותר מ-3 חודשים לטיול — "קטלוג מלונות" בלבד; פעולת התשלום פשוט אינה קיימת בתצוגה (בלי שורה מושבתת, בלי "בקרוב"). פחות מ-3 חודשים — "בחירת מלונות ותשלום אטרקציות" כשתי שורות פעולה עצמאיות. הסף האמיתי לא נקבע כאן — ייגזר מתאריכים/Monday. פאנל הדמו כולל בורר תרחיש + "⏱ הדמיית חלון 3 חודשים".
- **`JOURNEY_ACTIONS` — רישום מרכזי אחד לפעולות הלקוח:** שלב → 0 / 1 / כמה פעולות, ולכל פעולה `openMode` ו-`url` משלה. תת-מצב מצביע על פעולות לפי מזהה (`actions: ['hotels']`), וההגדרות חיות במקום אחד. `handleAction` ב-`App` מנתב לפי `openMode` בלבד — אין `if (stageId === ...)` ואין יעדים מקודדים בקומפוננטות. `openMode: null` = טרם נקבע כיצד הפעולה נפתחת. ארבעה מצבים אפשריים: `fillout` (טופס Fillout מוטמע) · `embedded` (תוכן חיצוני אחר) · `external` (פעולה שקורית מחוץ למר יפן, למשל Zoom) · `sheet` (מסך פנימי קיים). `url: null` = טרם סופקה כתובת אמיתית — לא ממציאים קישורים ולא מציגים טופס מדומה; לחיצה מציגה מצב "טרם חובר" (DEV בלבד).
- **מצב הטמעה נקבע בשתי בדיקות בלתי תלויות** (`EmbeddedActionSheet`): `fetch` ב-`mode:'no-cors'` מפריד "היעד לא נגיש" מ"נגיש אך לא מוצג", וקריאת `contentWindow.location` מזהה חסימת `X-Frame-Options`/`frame-ancestors` (frame חסום נשאר `about:blank` וניתן לקריאה). `loading` / `loaded` / `error`; היציאה לחלון חדש מוצעת רק במצב `error` וביוזמת הלקוח. אין עקיפת אבטחה.
- **הטמעת Fillout דרך החבילה הרשמית** `@fillout/react` (`FilloutStandardEmbed`), לא iframe אל כתובת העמוד. שרשרת ה-renderers: `EmbeddedActionSheet` → `ActionContentRenderer` → `FilloutRenderer` / iframe גנרי. הבחירה לפי ה-host של הפעולה (`*.fillout.com`). מזהה הטופס מגיע מהקונפיג (`filloutFormId`); מחרוזת השאילתה מומרת בשלמותה ל-prop הרשמי `parameters` — האפליקציה לא קוראת אף ערך ולא מציגה אותו. הספק מגיש את ההטמעה מ-`embed.fillout.com`. `filloutDomain` אופציונלי (דומיין מותאם) ואינו מוגדר כברירת מחדל. מוכנות נקבעת לפי `onInit` של הספק ושליחה לפי `onSubmit` שלו — **אין טיימר ואין ניחוש לפי frame חוצה-מקור**.
- **מלאי הקישורים מופרד לשלוש קבוצות** ב-`journeyConfig.ts`: `DEMO_ACTION_LINKS` (מאומת ומשויך — כרגע רק בחירת המלונות) · `UNASSIGNED_LINKS` (קישורים אמיתיים שתפקידם העסקי טרם אומת, לא מחוברים לשום שלב) · `AUTOMATION_WEBHOOKS` (Make — **לא** עמודי לקוח: לא מוטמעים, לא נפתחים מ-CTA, לא מופיעים ב-UI).
- **כלי DEV** — "🔎 בדיקת הטמעה של הקישורים" בפאנל הדמו: מריץ את אותה בדיקה על הקישורים האמיתיים במכשיר שמריץ את הפרוטוטייפ.
- **פעולת לקוח נפתחת בתוך האפליקציה:** הכתובות הן **אטומות** — מלאות כפי שהן ב-Monday (`DEMO_ACTION_LINKS` ב-`journeyConfig.ts`), בלי פירוק פרמטרים, בלי חילוץ מזהים ובלי בנייה מחדש. ב-`openMode: 'embedded'` ה-CTA פותח את `EmbeddedActionSheet` — גיליון גבוה (92% במובייל, מודאל בדסקטופ) עם iframe, מוכל בתוך מסך ה-iPhone, והמסך מאחור נשאר מעומעם במקומו. ה-UI אינו מפרש את הכתובת: לא מפרק פרמטרים, לא מחלץ מזהים ולא מנהל מזהה לקוח. הרכיב גנרי — ישמש גם לטופס שינויים ולפידבק.
- **כלל הפעולות:** פעולה אחת פתוחה → CTA ראשי חזק (`ctaFull`, למשל "לבחירת המלונות ←"). כמה פעולות במקביל → שורות קומפקטיות 46–48px בצורה `[אייקון] שם הפעולה … [CTA ←]` (`cta` הקצר), כל השורה לחיצה והפיל הוא ה-affordance (לא חץ בלבד). אין אזור פעולות כשאין פעולה אמיתית, ואין עיגולי בחירה ליד פעולות.
- **פעולת לקוח ≠ התקדמות במסע:** אחרי שליחה השורה מציגה "✓ נשלח" (אישור קבלה, ניטרלי) והמסע לא זז. רק כשהתהליך הפנימי מתעדכן השורה הופכת ל"✓ הושלם" (ירוק) והשלב יכול להיסגר. בדמו: "סימולציית עדכון Monday" — פנימי בלבד, הלקוח לעולם אינו רואה מינוח Monday.
- **מצב עצמאי לכל פעולה:** `pending` → `waitingForTeam` (הלקוח סיים את חלקו) → `completed` (V ב-Monday). לחיצה על CTA לעולם אינה מסמנת השלמה. השלב נסגר רק כשכל הפעולות שנדרשות *כרגע* הושלמו — ולכן פתיחת חלון האטרקציות מאוחר יותר מחזירה את השלב למצב פעיל, גם אם המלונות כבר אושרו.
- זרימת בחירת המלונות: טופס (checkboxes) → "סקירת הבחירות" → "סיכום הבחירות שלכם" ("חזרה לבחירות" משמרת) → שליחה → צפייה לקריאה בלבד. תשלום אטרקציות: sheet מסומלץ עם הערה שהחיבור לתשלום יוגדר לפי התהליך הקיים.
- אין כרטיס "השלב הבא" — פס ההתקדמות מספר מה בא אחר כך. במקומו, במידת הצורך, שורת עזר שקטה אחת (`afterNote`), למשל "לאחר השליחה, צוות מר יפן ימשיך מכאן.". ללא מקרא בפס.
- היררכיה בכרטיס: שם השלב (16px) ← שורת מצב אחת (תג פעולה · בעלות · מועד) ← משפט תומך אחד לכל היותר ← שורות הפעולה ← שורת עזר. ב"כל שלבי המסע": הושלם ✓ קומפקטי · נוכחי ● עם תג פעולה · עתידי ○ שקט עם בעלות מקוצרת.
- מרקם אסאנוהה (麻の葉) עדין כ-watermark מאחורי הדף (body::before, z:-1) — הכרטיסים והמודאלים נשארים נקיים.
- רקע אקוורל יפני בתוך כרטיס המסע (CardDecor: שכבת deco-bg): שטיפת שנהב, זוהר שמש פינתי, רכסים באובך, פוג'י עמום בשליש התחתון, פגודה קטנה — שפה אחת קבועה לכל השלבים, מאחורי כל התוכן.
- סדר השלבים (מתקדם): תוכנית בבנייה → תשלום שירות → פגישה → מילוי טופס שינויים → שינויים בתהליך → בחירת מלונות ואטרקציות → מלונות בהזמנה → אטרקציות בהזמנה → ביפן → מילוי פידבק.
- "מוכנים לטיסה" אינו אבן-דרך — "הכול מוכן לטיול" הוא תת-מצב סטטוס בתוך השלב הרלוונטי האחרון (החלטת stakeholder).
- חבילות: בסיסי 8 · סטנדרטי 9 · מתקדם 10 — הכול מ-`relevantStages(pkg)`, אפס hardcoding.
- Demo controls (משני): מצב לקוח/דמו · תרחיש 14 מצבים (מזיז את המצב בפועל) · Advanced: חבילה, שלב בפועל, שלב בתצוגה, תת-מצב.

## מיזוג לריפו האמיתי (במק)
מפת קבצים למיזוג — התאם שמות/נתיבים למבנה הקיים אצלך:
- `src/journeyConfig.ts` → מקור האמת: שלבים, תתי-מצבים, בעלות, חבילות, תרחיש, תוכן Sheets
- `src/components/JourneyPath.tsx` → פס ההתקדמות (תחנות לחיצות + preview) + שורת שלב/קישור
- `src/components/CurrentStagePanel.tsx` → תוכן השלב בכרטיס הבית + שורות הפעולה (`ActionRow`)
- `src/components/BottomSheet.tsx` + שימושיו ב-App → תשלום/פגישה/טופס/בחירות
- `src/components/HistoricalStagePanel.tsx` → צפייה בהיסטוריה (מצב לקוח)
- `src/components/JourneyFullView.tsx` → "כל שלבי המסע" (בדמו: תצוגה לכל שלב)
- `src/components/DemoControls.tsx` → צ'יפ Demo + תרחיש + Advanced
- `src/styles.css` → הטוקנים (:root) והמחלקות; אם יש לך design tokens קיימים — מפה אליהם
- `src/App.tsx` → חיווט: currentStage/previewStage, auto-advance, sheets, mode

## בדיקת ההטמעה מחוץ לסביבת התצוגה
דף ה-Artifact חוסם iframes חיצוניים ב-CSP, ולכן **אינו** סביבת בדיקה קבילה להטמעה.
לבדיקה אמיתית:
```
npm install
npm run dev          # http://localhost:5173
```
ואז: הצ'יפ Demo ← Advanced ← "בחירת מלונות" ← לחיצה על ה-CTA. לבדיקת שלושת
הטפסים בשלוש וריאציות (כתובת ישירה / הטמעה רשמית / הטמעה + דומיין מותאם):
Demo ← "🔎 בדיקת הקישורים האמיתיים".
אם הטופס אינו מוצג — DevTools ← Console; הודעת `X-Frame-Options` / `frame-ancestors`
היא התשובה, והיא אינה ניתנת ללכידה מקוד.

## אספקת קישורי הפעולה (`src/actionLinks.ts`)
חוזה אחד לפרוטוטייפ ולפרודקשן: `resolveActionLink({ actionId, clientId }) → { url }`.
היום המקור הוא הקונפיג המקומי; בפרודקשן מחליפים מקור אחד
(`setActionLinkSource`) בקריאה לבקאנד, שהוא זה שמדבר עם Monday/Make ומחזיר את
הכתובת המלאה. הפרונט מקבל כתובת אטומה בלבד ואינו מחזיק טוקנים.
`DEMO_CLIENT.clientId` הוא מזהה בדיקה פנימי — לא מוצג בשום ממשק.
